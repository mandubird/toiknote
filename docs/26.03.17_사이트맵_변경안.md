# 사이트맵정리_변경안.md
## TOEAI UX/IA 재설계안 (코칭 중심 구조 개편안)

---

# 0. 문서 목적

이 문서는 기존 `사이트맵정리.md`를 기준으로,  
현재 TOEAI의 라우팅/폴더 구조/기능 위치를 유지 가능한 범위에서 재정리하면서도

- **마케팅 관점에서 훅이 더 잘 걸리고**
- **사용자가 “점수가 오를 것 같은 느낌”을 더 강하게 받고**
- **실제 학습 행동으로 이어지며**
- **유료 결제 전환이 더 잘 일어나도록**

전체 IA(정보 구조), 하단 탭, 페이지 역할, 기능 위치, 폴더 역할을 재설계한 문서다.

핵심 방향은 한 줄로 정리하면 다음과 같다.

> **“분석 앱”에서 “코칭 앱”으로 바꾼다.**

즉, 기능을 보여주는 구조가 아니라  
**지금 상태 → 왜 그런지 → 오늘 뭘 해야 하는지 → 결제하면 무엇이 더 좋아지는지**  
가 자연스럽게 이어지는 구조로 바꾼다.

---

# 1. 현재 구조의 핵심 문제

## 1-1. 홈의 역할이 잘못 잡혀 있음

현재 홈(`/`)은 사실상 **오답노트 허브** 역할이다.

- 최근 오답 3개
- 전체 오답 리스트
- 파트/태그/클리어 필터
- 카메라 버튼으로 오답 등록

이 구조는 “데이터 저장/관리”에는 맞지만,  
사용자가 앱을 열었을 때 가장 먼저 보고 싶은 것은 이게 아니다.

사용자가 가장 먼저 궁금한 것은:

- 내가 지금 몇 점 수준인지
- 목표까지 얼마나 남았는지
- 내가 왜 점수가 안 오르는지
- 오늘 무엇을 해야 하는지

즉 홈은 **저장소**가 아니라 **코칭 화면**이어야 한다.

---

## 1-2. 오답노트가 너무 중요 기능인데 홈 안에 숨어 있음

오답노트는 TOEAI의 핵심 원재료다.

- 약점 분석의 근거
- 전략 생성의 근거
- 점수 예측의 근거
- 주간 리포트의 근거

그런데 이 중요한 자산이 홈 화면의 일부 리스트처럼 들어가 있으면  
사용자는 이것을 “핵심 기능”이 아니라 “부가 자료”처럼 느낀다.

즉, **오답노트는 별도 탭으로 승격**되어야 한다.

---

## 1-3. 약점 탭의 메시지와 실제 데이터가 충돌할 가능성

현재 약점(`/stats`)에 진입했을 때  
“아직 오답 데이터가 없어요. 오답을 3개 이상 등록하면 체크리스트가 생성돼요!”  
같은 메시지가 나오는데, 실제 홈에는 이미 오답이 14개 있는 상태라면  
사용자는 다음과 같이 느낀다.

- 데이터가 날아갔나?
- 앱이 불안정한가?
- 이 분석을 믿어도 되나?

토익 서비스에서 이건 치명적이다.  
토익은 **신뢰가 전부**이기 때문이다.

---

## 1-4. 정보가 여러 페이지에 분산되어 있음

현재 구조상 다음 정보가 여러 화면에 흩어져 있다.

- Top3 약점
- 미션
- 전략
- 로드맵
- 프로그램 진행
- D-day 기반 압축 모드
- 점수 변화

이렇게 정보가 분산되면 사용자는 앱을 돌아다니며 이해해야 한다.  
하지만 잘 만든 학습 앱은 반대로 움직인다.

> **앱이 먼저 정리해서 보여줘야 한다.**

---

## 1-5. 유료 결제 가치가 UX 상에서 선명하지 않음

현재 결제 유도는 주로:

- 무료 체험 배너
- 업그레이드 페이지
- 전략/프로그램 내 Pro 유도
- 설정의 구독·결제 탭

으로 이루어져 있다.

하지만 사용자는 단순히 “더 많은 기능”보다도  
**“결제하면 내 점수가 어떻게 달라지는지”**를 보고 결제한다.

즉, 유료 전환 UX는  
기능 잠금이 아니라 **결과 강화형 구조**로 재배치해야 한다.

---

# 2. 재설계 핵심 원칙

## 원칙 1. 홈은 저장소가 아니라 코칭 화면이어야 한다

앱을 열자마자 3초 안에 보여야 할 것은:

1. 현재 상태
2. 오늘 할 일
3. 가장 위험한 약점
4. 시험일까지 전략적 위치

이다.

---

## 원칙 2. 오답노트는 독립 탭으로 승격한다

오답노트는 “홈 안의 리스트”가 아니라  
**별도의 학습 자산 관리 공간**이 되어야 한다.

---

## 원칙 3. 약점은 ‘근거 화면’이어야 한다

약점 탭은 “없어요”가 먼저 보이는 페이지가 아니라  
**왜 지금 이런 전략이 나왔는지 설명하는 근거 화면**이어야 한다.

---

## 원칙 4. 프로그램/전략/대시보드 중복을 줄인다

지금 구조는 기능 단위로 페이지가 나뉘어 있다.  
하지만 사용자는 기능보다 흐름으로 이해한다.

그래서 구조를 다음처럼 바꾼다.

- 코칭: 지금 상태 + 오늘 할 일
- 노트: 오답 저장/관리
- 약점: 왜 틀리는지 근거
- 전략: 시험일까지의 플랜
- 설정: 내 정보/결제

---

## 원칙 5. 유료는 “결과 심화” 중심으로 보이게 한다

무료 사용자도 기본 진단은 가능해야 한다.  
하지만 유료에서만 제공되는 가치는 다음처럼 보이게 해야 한다.

- 더 깊은 리포트
- 더 구체적인 전략
- 더 강한 점수 예측
- PDF 저장/리포트
- 장기 계획/주차 리포트

즉 “더 많은 기능”이 아니라  
**“더 높은 확률로 점수를 올리는 구조”**로 보여야 한다.

---

# 3. 변경 후 전체 사이트맵

## 3-1. 하단 탭 구조 (변경안)

기존:
- 홈
- 대시보드
- 약점
- 전략
- 설정

변경:
- **코칭**
- **노트**
- **약점**
- **전략**
- **설정**

---

## 3-2. 각 탭의 역할

### 1) 코칭 (`/` 또는 `/coaching`)
앱의 메인 홈.

보여줘야 할 것:
- 현재 예상 점수 / 목표 점수
- D-day / 진행률
- 오늘 해야 할 일 3개
- 약점 TOP3
- 이번 주 포커스
- 최근 변화(있을 경우)
- Pro 가치 미리보기

핵심 질문:
> “그래서 오늘 뭘 해야 하지?”

---

### 2) 노트 (`/notes` 또는 기존 `/`의 역할 이동)
오답노트 전용 공간.

보여줘야 할 것:
- 전체 오답 리스트
- 최근 등록 오답
- 파트/태그/클리어 필터
- 오답 상세(`/note/:id`)
- 카메라 등록 CTA

핵심 질문:
> “내 오답을 어떻게 관리하고 복습하지?”

---

### 3) 약점 (`/stats`)
약점 분석 전용 공간.

보여줘야 할 것:
- 파트별 분포
- 태그 TOP
- 세그먼트(Part5/Part7/Part2/시간부족) 분석
- 약점 체크리스트
- 왜 이 약점이 위험한지 설명
- Pro 심화 분석 유도

핵심 질문:
> “왜 점수가 안 오르지?”

---

### 4) 전략 (`/strategy`)
시험일까지의 실행 전략.

보여줘야 할 것:
- D-day 모드(일반/압축/고압축/생존)
- 이번 주 전략
- 주차별/구간별 플랜 요약
- 고득점용 압축 전략
- Pro 전략 리포트 / PDF / 예측 심화

핵심 질문:
> “시험일까지 어떤 순서로 공부해야 하지?”

---

### 5) 설정 (`/settings`)
내 정보/결제/정책/앱 정보.

보여줘야 할 것:
- 계정/프로필
- 현재 점수/목표 점수/시험일
- 구독 상태
- 결제 진입
- 정책/환불/사업자 정보

핵심 질문:
> “내 정보와 구독 상태는 어떻지?”

---

# 4. 기존 메뉴와 기능이 어디로 가는지 상세 이동표

## 4-1. 하단 탭 기준 이동표

| 기존 | 새 위치 | 변경 이유 |
|---|---|---|
| 홈(`/`) | 노트 탭으로 역할 이동 | 현재 홈은 사실상 오답노트 허브이기 때문 |
| 대시보드(`/dashboard`) | 코칭 탭의 핵심 정보로 흡수 | 점수/Top3/미션/진행률은 홈에서 보여줘야 함 |
| 약점(`/stats`) | 약점 유지 | 근거 화면 역할로 강화 |
| 전략(`/strategy`) | 전략 유지 | 실행 계획 중심으로 재정리 |
| 설정(`/settings`) | 설정 유지 | 정보/결제/정책 허브 유지 |

---

## 4-2. 페이지 기준 상세 이동표

### A. 홈(`src/pages/HomePage.jsx`)
기존 역할:
- 최근 오답 3개
- 전체 오답 리스트
- 파트/태그/클리어 필터
- 코치 한 줄 일부 표시

변경 후:
- **노트 페이지** 역할로 이동
- 파일명도 장기적으로 `NotesPage.jsx`로 바꾸는 것이 좋음

홈에서 제거할 것:
- 전체 오답 리스트 중심 구조
- 홈을 차지하는 필터/목록형 레이아웃

홈에 남길 수 있는 것:
- “오늘 등록한 오답 수”
- “바로 등록 CTA”
- “최근 오답 1~2개 미리보기” 정도만 카드로 축소

---

### B. 대시보드(`src/pages/DashboardPage.jsx`)
기존 역할:
- 예상 점수/목표 점수/진행률
- 약점 Top3
- 로드맵
- 점수 변화
- ScoreBand 전략 카드
- One-line 조언

변경 후:
- **코칭 메인 화면의 핵심 데이터 공급원**으로 승격
- 독립 탭으로 유지하지 않고, 홈/코칭의 핵심 섹션으로 흡수

이동 방식:
- `getDashboardSummary(userId)`는 계속 사용
- 단, 렌더링 위치를 `/dashboard`가 아니라 코칭 메인에서 소비

대시보드 페이지는:
- 유지하더라도 “상세 보기” 성격으로 축소
- 또는 향후 코칭으로 완전히 통합 가능

---

### C. 통계(`src/pages/StatsPage.jsx`)
기존 역할:
- 파트 분포
- 태그 TOP
- 세그먼트 분석
- 유료/무료에 따른 상세 블록 차등

변경 후:
- **약점의 근거 화면**으로 재정의

추가해야 할 것:
- 데이터 있을 때는 무조건 무엇인가 보여주기
- “데이터 없음” 메시지는 조건 정확히 수정
- 약점이 왜 위험한지 설명하는 마이크로카피 추가
- 코칭/전략에서 본 내용과 연결되게 문구 맞추기

예:
- “현재 접속사 유형이 가장 큰 감점 요인입니다.”
- “Part7 시간 부족이 목표 점수 달성을 막고 있어요.”

---

### D. 전략(`src/pages/StrategyPage.jsx`)
기존 역할:
- 시험일까지 남은 일수 기반 모드 표시
- 유료 사용자일 때 AI 전략 분석

변경 후:
- **행동형 전략 페이지**로 개편

강화할 것:
- 모드 표시만 하지 말고 이번 주 액션 중심으로 표현
- D-73이면 “정상 모드”가 아니라 “이번 주에 무엇을 줄이고 무엇을 집중할지” 제시
- 코칭 화면과 전략 페이지 문구를 연결

즉:
- 홈에서 “오늘 할 일”
- 전략에서 “이번 주 플랜/시험일까지 큰 흐름”

으로 역할을 명확히 분리

---

### E. 프로그램(`src/pages/ProgramPage.jsx`)
기존 역할:
- 시험일 기반 전략 플랜 진행
- 블록/압축 모드 UI
- 주차(구간) 진행
- 리포트 조회/표시

변경 후:
- **전략 페이지 하위 기능으로 재배치**
- 사용자가 하단 탭에서 따로 “프로그램”을 찾을 필요가 없게 함

권장 구조:
- 전략 페이지 내에서 프로그램 요약 보여주기
- 상세 주차/구간 화면은 서브 라우트 유지
- 진입만 전략 페이지에서 하도록 정리

즉:
- 전략 = 개요
- week/report = 상세

---

### F. 설정(`src/pages/SettingsPage.jsx`)
기존 역할:
- 내 정보
- 구독·결제
- 정책/사업자 정보
- `/settings?pay=1`로 결제 탭 오픈

변경 후:
- 역할 유지
- 다만 결제 진입은 계속 여기로 모으되, 사용자 인식은 “설정”이 아니라 “업그레이드/결제”로 더 명확히 보여야 함

추가 권장:
- 상단에 현재 플랜/무료 체험 상태 더 선명히
- “결제 시 얻는 결과”를 먼저 보여주기
- 정책/사업자 정보는 하단 유지

---

### G. 업그레이드(`/upgrade`)
기존 역할:
- 무료 체험 종료/플랜 종료 시 업그레이드 유도

변경 후:
- 역할 유지
- 다만 카피를 기능 중심이 아니라 결과 중심으로 수정

예:
- “전체 전략 플랜은 Pro 전용이에요”보다
- “목표 점수까지 필요한 전략 리포트는 Pro에서 확인할 수 있어요”

가 더 좋음

# 5. 변경 후 권장 사용자 여정

## 5-1. 비로그인 유입
랜딩 → 로그인 → 무료 진단(선택) → 코칭 홈

핵심:
- 로그인 후 바로 오답 리스트가 아니라
- “현재 상태 + 오늘 할 일”을 먼저 보게 함

---

## 5-2. 오답 등록
코칭 또는 노트에서 카메라 CTA → 이미지 분석 → 확인/수정 → 저장

저장 후 기대 동작:
- 코칭의 오늘 할 일/약점/예상 점수에 반영
- 노트에 새 오답 저장
- 약점 탭 데이터 반영
- 전략 탭 포커스 업데이트

즉 저장 후 각 탭이 살아 움직여야 함

---

## 5-3. 전략 확인
코칭에서 “이번 주 전략 보기” → 전략 페이지 → 주차/구간 상세 → 리포트

즉 사용자가 앱을 배회하는 구조가 아니라
**코칭 → 전략 → 상세 리포트**로 자연스럽게 흐르게 한다

---

## 5-4. 결제 유도
무료 사용자:
- 코칭에서 Pro 심화 미리보기
- 전략 페이지에서 상세 전략 잠금
- 약점 페이지에서 심화 분석 잠금
- 리포트/PDF 잠금
- CTA는 모두 `/settings?pay=1`

# 8. 컴포넌트/서비스 위치 변경 상세

## 8-1. 유지 가능 서비스

기존 서비스는 대부분 유지 가능하다.

- `programService.getDashboardSummary(userId)`
- `fetchWrongAnswers(userId)`
- `fetchTagStats`

- `getSubscription`
- `analyzeToeicImage`
- `saveWrongNoteWithStats`
- `requestPlanPayment`

즉, 백엔드/서비스를 크게 뜯기보다  
**어디에서 무엇을 보여줄지**가 핵심이다.

---

## 8-2. 코칭 페이지에서 재사용할 데이터

코칭 페이지는 새로 만들되, 완전히 새 논리로 갈 필요는 없다.

재사용 가능한 데이터:
- 예상 점수/목표 점수/진행률: `getDashboardSummary`
- Top3 약점: `getDashboardSummary` 또는 `tagStatsService`
- 오늘 해야 할 일: `strategy_text`/summary 가공
- D-day/프로그램 상태: `programService`
- 유료 상태: `getSubscription`

---

## 8-3. 노트 페이지에서 옮겨갈 요소

기존 HomePage에 있던:
- 오답 리스트
- 필터
- 최근 오답
- 카메라 CTA 보조 연결

이들은 노트 탭으로 이동

- 홈 → 코칭(`/`)

# 12. 최종 한 줄 정리

기존 구조는  
> **오답을 저장하고 통계를 보는 앱**에 가깝다.

변경 후 구조는  
> **점수를 올리기 위해 오늘 무엇을 해야 하는지 안내하는 코칭 앱**이 되어야 한다.

즉 최종 방향은 다음이다.

- 홈 = 코칭
- 오답 = 노트로 분리
- 약점 = 근거
- 전략 = 실행 순서
- 결제 = 결과 심화

이렇게 바뀌어야 마케팅 훅도 강해지고,  
사용자도 “이 앱이 나를 900으로 데려가겠다”는 느낌을 받는다.
