## 8️⃣ 결제 및 접근 제어

| 항목 | 구현 | 상태 |
|------|------|------|
| 결제 성공 시 active + start + end(60일) + currentWeek=1 | `PaymentSuccessPage` → `startProgramV403` (56일 설정됨) | ⚠️ **60일이 아니라 56일(8주)** |

## 요약: “요구사항 기준으로 개발된 거냐” / “v4.1이랑 겹치냐”

- **v4.1 명세 = 지금 적어주신 11개 항목과 같은 내용**이라, **완전히 겹칩니다.**
- **요구사항 기준으로 “이미 구현된 부분”**  
  - User 확장(estimated 제외), 시간 데이터, Part7 패널티, 8주 템플릿, 대시보드 UI, 주간 리포트 화면, 결제 후 프로그램 시작, 만료/업그레이드 **안내** 페이지까지는 구현돼 있음.
- **아직 안 된 부분**  
  - **점수 예측**: Part1~7 개별 정확도·Part7/Part5 가중치 미반영.  
  - **트리거**: “매주 일요일”, “모의고사 입력 시” 자동 갱신 없음.  
  - **주차 자동 증가**: Cron 없음, 수동 진행만.  
  - **60일**: 현재는 56일(8주)로 설정됨 → 60일로 바꾸려면 endDate 계산만 수정하면 됨.  
  - **접근 제어**: `programStatus != active`일 때 전역 `/upgrade` 리다이렉트 없음.  
  - **연장**: 30일 연장 시 `programEndDate` 갱신하는 결제 후 로직 없음.  
  - **관리자 페이지**: 미구현.  
  - **users.estimated_score**: 컬럼 없음(예측은 `score_prediction` 테이블만 사용).

원하시면 “60일로 변경”, “주차 자동 증가 Cron”, “연장 결제 시 endDate 갱신”, “점수 공식 가중치 반영” 중에서 우선순위 정해서 구현 단계도 정리해 드리겠습니다.
