**v1.0 | 2026.03.18**

## 1. 개요 및 변경 배경

### 현재 문제

현재 전략 페이지의 "지금 먼저 고쳐야 할 영역" 섹션은 아래처럼 구성되어 있다.

```
문장구조 (3개)
지금은 이 영역을 먼저 줄이는 게 점수 효율이 높아요

이해 (2개)
지금은 이 영역을 먼저 줄이는 게 점수 효율이 높아요

details (2개)
지금은 이 영역을 먼저 줄이는 게 점수 효율이 높아요
```

**문제점 3가지**

1. **복붙 문장**: 모든 항목에 동일한 문장이 반복됨 → 어떤 태그에 붙여도 말이 되는 무의미한 문장
2. **전략 없음**: 전략 페이지인데 전략 설명이 없고, 분류명만 나열함
3. **신뢰 손실**: 유저가 1~2번 보면 AI가 실제로 분석한 게 아님을 눈치채고 이탈

### 목표

각 항목 카드가 **"우선순위 + 이유 + 행동"** 3요소를 포함하도록 변경한다.
문장은 유저의 실제 오답 데이터를 기반으로 **AI가 동적 생성**한다.

## 2. UI/UX 변경 명세

### 2.1 섹션 제목 변경

| 현재 | 변경 |
|------|------|
| 지금 먼저 고쳐야 할 영역 | 지금 우선 교정할 약점 |

> **선택 이유**: "고쳐야 할 영역"은 막연하다. "우선 교정할 약점"은 순서와 행동이 함께 담긴다.

### 2.2 카드 구조 변경

#### 현재 구조
```
[영역명] (N개)
[동일 반복 문장]
```

#### 변경 후 구조
```
[영역명] (N개)   ← 유지
[원인형 1줄]     ← NEW: 왜 이 영역이 우선인지 / 어떤 실수 패턴인지
[행동형 1줄]     ← NEW: 오늘 구체적으로 뭘 하면 되는지
```

**카드 1개 예시 (최종 렌더링)**

```typescript
const { data: wrongAnswers } = await supabase
  .from("wrong_answers")
  .select("tag, part, created_at, memo")
  .eq("user_id", userId)
  .order("created_at", { ascending: false })
  .limit(50); // 최근 50개 기준

// 태그별 집계
const tagSummary = wrongAnswers.reduce((acc, item) => {
  acc[item.tag] = (acc[item.tag] || 0) + 1;
  return acc;
}, {});

// 상위 3개 태그 추출 (오답 수 기준)
const topTags = Object.entries(tagSummary)
  .sort((a, b) => b[1] - a[1])
  .slice(0, 3)
  .map(([tag, count]) => ({ tag, count }));
```

### 3.3 응답 파싱 및 폴백 처리

```typescript
interface PriorityCard {
  tag: string;
  count: number;
  reason: string;
  action: string;
}

async function getPriorityCards(userId: string): Promise<PriorityCard[]> {
  try {
    const response = await fetch("/api/strategy/priority-cards", {
      method: "POST",
      body: JSON.stringify({ userId }),
    });
    const data = await response.json();
    return data.priority_cards;
  } catch {
    // 폴백: AI 실패 시 정적 템플릿으로 대체
    return topTags.map((t) => getFallbackCard(t.tag, t.count));
  }
}

// 폴백 템플릿 (AI 실패 시)
function getFallbackCard(tag: string, count: number): PriorityCard {
  const fallbacks: Record<string, Omit<PriorityCard, "tag" | "count">> = {
    문장구조: {
      reason: "최근 오답에서 가장 많이 반복된 약점입니다.",
      action: "오늘은 핵심 문장 구조 파악 연습 10문제가 우선입니다.",
    },
    이해: {
      reason: "정답 근거 연결이 약해 반복 실수가 나오고 있습니다.",
      action: "문제 풀이 후 정답 근거를 한 줄로 직접 적어보세요.",
    },
    details: {
      reason: "세부정보 함정 표현에서 반복적으로 흔들리고 있습니다.",
      action: "오늘은 세부정보 문제만 골라 오답 근거까지 체크하세요.",
    },
  };
  return {
    tag,
    count,
    ...(fallbacks[tag] ?? {
      reason: "최근 오답에서 반복 패턴이 확인된 약점입니다.",
      action: "오늘 이 영역 문제를 집중해서 보정하세요.",
    }),
  };
}
```

### 5.4 Route 구현 (`app/api/strategy/priority-cards/route.ts`)

```typescript
import { NextRequest, NextResponse } from "next/server";
import { createClient } from "@supabase/supabase-js";
import OpenAI from "openai";

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

export async function POST(req: NextRequest) {
  const { userId } = await req.json();

  // 1. 오답 데이터 조회
  const supabase = createClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!
  );

  const { data: wrongAnswers } = await supabase
    .from("wrong_answers")
    .select("tag, part, created_at, memo")
    .eq("user_id", userId)
    .order("created_at", { ascending: false })
    .limit(50);

  if (!wrongAnswers || wrongAnswers.length === 0) {
    return NextResponse.json({ priority_cards: [] });
  }

  // 2. 태그별 집계 + 상위 3개
  const tagSummary = wrongAnswers.reduce<Record<string, number>>((acc, item) => {
    acc[item.tag] = (acc[item.tag] || 0) + 1;
    return acc;
  }, {});

  const topTags = Object.entries(tagSummary)
    .sort((a, b) => b[1] - a[1])
    .slice(0, 3)
    .map(([tag, count]) => ({ tag, count }));

  // 3. OpenAI 호출
  const prompt = buildPrompt(topTags, wrongAnswers.slice(0, 10));

  const completion = await openai.chat.completions.create({
    model: "gpt-4o-mini",
    messages: [{ role: "user", content: prompt }],
    response_format: { type: "json_object" },
    temperature: 0.7,
  });

  const result = JSON.parse(completion.choices[0].message.content || "{}");

  return NextResponse.json(result);
}

function buildPrompt(
  topTags: { tag: string; count: number }[],
  recentAnswers: { tag: string; memo: string | null }[]
): string {
  return `
당신은 토익 AI 코치입니다.
아래는 유저의 최근 오답 데이터입니다. 이 데이터를 분석해서 각 약점 태그별 코칭 카드를 생성하세요.

[유저 오답 요약]
${topTags.map((t) => `- ${t.tag}: 최근 ${t.count}개 오답`).join("\n")}

[오답 메모 샘플]
${recentAnswers.map((w) => `- [${w.tag}] ${w.memo || "메모 없음"}`).join("\n")}

[응답 형식 - JSON만 반환]
{
  "priority_cards": [
    {
      "tag": "태그명",
      "count": 오답수,
      "reason": "왜 우선인지 or 어떤 실수 패턴인지 (1문장, 40자 이내)",
      "action": "오늘 구체적으로 뭘 하면 되는지 (1문장, 40자 이내)"
    }
  ]
}

[규칙]
- 모든 카드에 같은 문장 절대 금지. 태그별로 완전히 다른 내용 작성.
- reason: "원인형"(반복 패턴 설명) or "증상형"(어떻게 틀리는지) 중 택1
- action: 항상 "행동형" — 오늘 당장 할 수 있는 구체적 액션
- reason과 action이 서로 보완 관계가 되도록 작성
- JSON 외 다른 텍스트 없이 JSON만 반환
`.trim();
```

## 6. 캐싱 전략

```
전략 페이지 로딩 시마다 OpenAI를 호출하면 비용이 증가한다.
아래 캐싱 규칙을 적용한다.
```

### 6.1 캐싱 규칙

| 조건 | 처리 |
|------|------|
| 오늘 처음 전략 페이지 진입 | OpenAI 호출 후 결과를 DB에 저장 |
| 같은 날 재진입 | DB에서 캐시된 결과 반환 (OpenAI 미호출) |
| 새 오답 등록 후 재진입 | 캐시 무효화 → OpenAI 재호출 |

### 6.2 캐시 테이블

```sql
CREATE TABLE strategy_cache (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID REFERENCES users(id),
  cache_date   DATE NOT NULL,                  -- 생성일 (일 단위)
  cards_json   JSONB NOT NULL,                 -- priority_cards 배열
  wrong_count  INTEGER NOT NULL,               -- 캐시 생성 시점 오답 수
  created_at   TIMESTAMPTZ DEFAULT NOW(),

  UNIQUE (user_id, cache_date)
);
```

### 6.3 캐시 조회 로직

```typescript
async function getPriorityCardsWithCache(userId: string) {
  const today = new Date().toISOString().split("T")[0];

  // 1. 현재 오답 수 조회
  const { count: currentWrongCount } = await supabase
    .from("wrong_answers")
    .select("*", { count: "exact", head: true })
    .eq("user_id", userId);

  // 2. 오늘 캐시 존재 여부 확인
  const { data: cache } = await supabase
    .from("strategy_cache")
    .select("*")
    .eq("user_id", userId)
    .eq("cache_date", today)
    .single();

  // 3. 캐시 유효하면 반환 (오답 수 변화 없을 때)
  if (cache && cache.wrong_count === currentWrongCount) {
    return cache.cards_json;
  }

  // 4. 캐시 없거나 오답 추가됐으면 AI 재호출
  const freshCards = await callOpenAI(userId);

  // 5. 캐시 저장 (upsert)
  await supabase.from("strategy_cache").upsert({
    user_id: userId,
    cache_date: today,
    cards_json: freshCards,
    wrong_count: currentWrongCount,
  });

  return freshCards;
}
```

## 7. 문구 가이드 (Cursor AI 참고용)

AI 응답 품질이 낮거나 폴백 상황일 때 사용할 정적 문구 레퍼런스.
프롬프트 튜닝 시에도 아래 예시 스타일을 참고한다.

### 7.1 원인형 문구 예시

- 최근 오답에서 가장 많이 반복된 약점입니다.
- 점수 손실이 가장 큰 영역으로 먼저 교정할 가치가 높아요.
- 시간 부족을 유발하는 핵심 원인 중 하나입니다.
- 다른 약점의 뿌리 원인이 되는 영역입니다.

### 7.2 증상형 문구 예시

- 긴 문장에서 핵심 주어·동사 관계를 놓치는 패턴이 보입니다.
- 정답 근거를 끝까지 연결하지 못하고 문장 단위 해석에서 멈추고 있어요.
- 키워드는 찾지만 동의어·부정 표현에서 흔들리는 패턴입니다.
- 지문 전체 흐름보다 문장 단위로 해석할 때 자주 틀립니다.

### 7.3 행동형 문구 예시

- 오늘은 수식어를 걷어내고 핵심 문장만 잡는 연습 10문제가 우선입니다.
- 문제를 푼 뒤 정답 근거 한 줄을 직접 적어보는 훈련이 필요해요.
- 세부정보 문제만 따로 풀고, 오답 근거 표현까지 체크해보세요.
- 오늘은 키워드 매칭 대신 동의어 표현 체크 중심으로 좁혀보세요.

### 7.4 조합 예시 (reason + action)

```
[문장구조]
reason: 긴 문장에서 핵심 주어·동사 관계를 놓쳐 오답이 반복되고 있어요.
action: 오늘은 수식어를 걷어내고 핵심 문장만 잡는 연습 10문제가 우선입니다.

[이해]
```
