```
❓ "RC 시간 분배 어떻게 해요?"
  → AI: "Part 5 강함/Part 7 취약 → Part 5(15분), Part 6(10분), Part 7(50분)"
```

## 🔬 파트별 약점 분석: 실제로 정확한가? (데이터 vs AI 생성)

**결론부터:**  
- **숫자·분포(몇 개, 몇 %, 몇 초)** → **실제 유저 데이터를 DB에서 집계한 값**이라서 “측정 가능”하고, 그만큼은 **실제로 분석 가능**하다.  
- **문법/함정/패턴 라벨(시제, 우회답변 등)** → **문제 하나하나를 GPT가 분류**한 뒤 그걸 DB에 넣고 집계하는 구조라, **분류 정확도에 따라 오차**가 있다.  
- **전략 문장·팁·점수 예측 문구** → **GPT가 위 통계를 입력받아 생성하는 “이야기”**에 가깝다. 데이터 기반이지만, 그 자체는 “측정값”이 아니다.

아래처럼 구분해서 설계·운영하는 걸 권장한다.

### ✅ 실제로 “측정·집계”되는 것 (데이터 기반)

| 항목 | 출처 | 비고 |
|------|------|------|
| Part별 오답 개수, LC/RC 비율 | 사용자가 저장한 오답만 DB에서 COUNT | **100% 실제** |
| Part 5 “시제 8개, 관계대명사 4개” | 문제별로 GPT가 **한 번씩** 분류 → DB 저장 → **우리가 COUNT** | 숫자(개수)는 실제; “시제”라는 **라벨**은 GPT 분류 결과 |
| Part 7 평균 풀이 시간, 시간 부족 비율 | 사용자 입력(타이머/체크) 또는 앱 측정 → DB 집계 | **실제** (입력이 정확하면) |
| Part 2 “우회답변 75% 오답” | 문제별 GPT 분류(우회/직접 등) → DB 저장 → 비율 계산 | 비율은 실제; **유형 라벨**은 GPT 분류 |
| Part 3 “3번 문제 오답률” | set_position(1/2/3) 저장 후 집계 | **실제** (번호 입력이 맞다면) |

→ 즉, **“몇 개, 몇 %, 몇 초”**는 모두 **저장된 데이터의 집계**라서, “클로드/챗GPT가 그냥 말한 숫자”가 아니라 **실제로 분석 가능한 수치**다.  
다만 **“시제”, “우회답변”, “함정 유형”** 같은 **이름(라벨)**은 전부 **GPT가 문제 하나하나 보고 붙인 것**이라, GPT가 잘못 분류하면 그만큼 통계도 어긋난다.

### ⚠️ GPT가 “이야기”하는 것 (생성·권장)

| 항목 | 설명 |
|------|------|
| “시제 개념서 집중하세요”, “지문 구조 파악 훈련 2주” | GPT가 **위에서 만든 통계를 입력으로** 받아 생성한 **전략 문장** |
| “4주 후 +80점 예상”, “900점 도달 확률 64%” | **공식/모델**을 쓰면 일부는 데이터 기반이 될 수 있지만, 현재 설계상 **의도는 “동기 부여”**에 가깝고, 수치는 **산식 또는 GPT 생성** |
| specificTips 리스트 | 통계 기반이지만 **문장 자체는 GPT 생성** |

→ 이 부분은 **“실제 측정”이 아니라 “데이터를 바탕으로 한 AI 권장/설명”**이라고 보는 게 맞다.

### 📌 정리: 그래서 파트별 약점 분석이 “실제로” 가능한가?

- **가능한 것**
  - Part별 **몇 개 틀렸는지**, **어느 유형(라벨)에 몇 개가 몰려 있는지** → **DB 집계로 실제 분석 가능**.
  - Part 7 **풀이 시간·시간 부족 비율** → 사용자/앱이 준 데이터만 정확하면 **실제 분석 가능**.
  - “시제 8개, 우회답변 75%” 같은 **숫자** → **저장된 분류 결과를 집계한 값**이라, “그냥 이야기”가 아니라 **데이터 기반 지표**다.

- **오차가 나는 부분**
  - **문제 하나하나의 라벨(시제/우회답변/함정 유형 등)**을 GPT가 잘못 붙이면, 그 라벨로 만든 통계도 그만큼 틀어짐.
  - 전략 문장·팁·점수 예측 문구는 **생성된 내용**이라, “측정값”이 아님.

- **제품에서 신뢰 쌓는 방법**
  - 화면에 **“이 숫자는 당신이 푼 ○○문제 기준 집계예요”**처럼 **데이터 출처(문제 수, 기간)**를 같이 보여 주기.
  - **전략/팁**은 “AI가 당신 데이터를 바탕으로 추천한 내용”이라고 명시.
  - 가능하면 **문법/유형 분류**는 **프롬프트·샘플 검증**으로 정확도 점검하고, 잘못된 라벨이 눈에 띄면 **사용자 수정(태그 수정)** 한 번 넣어 두면 좋음.

즉, **“파트별 약점 분석” 자체는 “실제 데이터 집계”로 구현 가능**하고, **그 숫자에 붙는 해석·전략·확률 문구**는 **GPT가 데이터를 보고 이야기하는 부분**이라고 보면 된다.

#### 3️⃣ Part 7 시간 부족 원인 분석
**목적**: 단순 "속도 문제"가 아니라 **"어떤 유형에서 시간을 많이 쓰나"** 분석

**DB 필드 추가:**
```javascript
{
  passageType: "단일지문" | "이중지문" | "삼중지문",
  questionType: "사실확인" | "추론" | "어휘" | "의도파악" | "문장삽입",
  solvingTime: number,           // 초 단위 (사용자 입력 또는 타이머)
  timeoutFlag: boolean           // "시간 부족으로 찍음" 체크박스
}
```

**분석 로직:**
```javascript
// 1. 평균 풀이 시간 계산
const avgPart7Time = totalTime / part7Count

// 2. 유형별 오답률
const inferenceWrongRate = inferenceWrong / inferenceTotal

// 3. 진단
if (avgPart7Time > 90) {  // 문제당 1분 30초 초과
  diagnosis = "속도 문제 - 스키밍 훈련 필요"
}

if (inferenceWrongRate > 0.6) {
  diagnosis = "추론 능력 부족 - 지문 구조 파악 훈련"
}

if (vocabularyWrongRate > 0.5) {
  diagnosis = "어휘 부족 - 토익 필수 어휘 암기"
}
```

**전략 출력 예시:**
```json
{
  "timeIssue": true,
  "avgTime": 120,
  "mainWeakness": "추론 문제",
  "weakPassageType": "삼중지문",
  "recommendation": "삼중지문 추론 문제에서 평균 2분 소요. 지문 구조 먼저 파악하는 훈련 2주 집중",
  "timeStrategy": "Part 5(15분) → Part 6(8분) → Part 7(52분)"
}
```

### 3. tag_stats 뷰 (자동 계산) — 전 파트 반영

**part_counts는 서브쿼리로 집계** (GROUP BY user_id만 하면 part별 개수 불가하므로).

```sql
CREATE VIEW tag_stats AS
SELECT 
  wn.user_id,
  COUNT(*) as total_wrong,
  SUM(CASE WHEN wn.lc_or_rc = 'LC' THEN 1 ELSE 0 END) as lc_wrong,
  SUM(CASE WHEN wn.lc_or_rc = 'RC' THEN 1 ELSE 0 END) as rc_wrong,
  
  -- Part별 통계 (서브쿼리)
  (
    SELECT jsonb_object_agg(part::text, cnt)
    FROM (
      SELECT part, COUNT(*) as cnt
      FROM wrong_notes wn2
      WHERE wn2.user_id = wn.user_id AND wn2.part IS NOT NULL
      GROUP BY part
    ) sub
  ) as part_counts,
  
  -- Part 1 함정 유형
  (
    SELECT jsonb_object_agg(image_trap_type, cnt)
    FROM (
      SELECT image_trap_type, COUNT(*) as cnt
      FROM wrong_notes wn2
      WHERE wn2.user_id = wn.user_id AND wn2.part = 1 AND image_trap_type IS NOT NULL
      GROUP BY image_trap_type
    ) sub
  ) as part1_trap_counts,
  
  -- Part 3 집중력: 3번 문제 오답 비율 (높으면 집중력 저하 의심)
  ROUND(
    COUNT(*) FILTER (WHERE wn.part = 3 AND wn.set_position = 3)::numeric /
    NULLIF(COUNT(*) FILTER (WHERE wn.part = 3), 0) * 100,
    1
  ) as part3_position3_rate,
  
  -- Part 5 문법 통계 (상위 5개)
  (
    SELECT jsonb_object_agg(grammar_category, cnt)
    FROM (
      SELECT grammar_category, COUNT(*) as cnt
      FROM wrong_notes wn2
      WHERE wn2.user_id = wn.user_id AND grammar_category IS NOT NULL
      GROUP BY grammar_category
      ORDER BY cnt DESC
      LIMIT 5
    ) sub
  ) as grammar_counts,
  
  -- Part 6 빈칸 유형
  (
    SELECT jsonb_object_agg(blank_type, cnt)
    FROM (
      SELECT blank_type, COUNT(*) as cnt
      FROM wrong_notes wn2
      WHERE wn2.user_id = wn.user_id AND wn2.part = 6 AND blank_type IS NOT NULL
      GROUP BY blank_type
    ) sub
  ) as part6_blank_counts,
  
  -- Part 7 유형별 통계
  (
    SELECT jsonb_object_agg(question_type, cnt)
    FROM (
      SELECT question_type, COUNT(*) as cnt
      FROM wrong_notes wn2
      WHERE wn2.user_id = wn.user_id AND wn2.part = 7 AND question_type IS NOT NULL
      GROUP BY question_type
      ORDER BY cnt DESC
    ) sub
  ) as part7_question_types,
  
  AVG(wn.solving_time) FILTER (WHERE wn.part = 7) as avg_part7_time,
  ROUND(
    COUNT(*) FILTER (WHERE wn.timeout_flag = TRUE)::numeric / 
    NULLIF(COUNT(*), 0) * 100, 
    1
  ) as timeout_rate

FROM wrong_notes wn
GROUP BY wn.user_id;
```

**장점:** 
- 트랜잭션 불필요
- 쿼리만으로 실시간 통계 조회
- 복잡한 집계도 SQL로 간단히 처리

## 💾 저장 로직 (Supabase 트랜잭션)

### 기존 방식 (단순 INSERT)
```javascript
// ❌ 나쁜 예: 통계 누적 안 됨
await supabase
  .from('wrong_notes')
  .insert(noteData)
```

### 새로운 방식 (트랜잭션)
```javascript
// ✅ 좋은 예: 한 번에 모든 업데이트
import { createClient } from '@supabase/supabase-js'

async function saveWrongNoteWithStats(noteData, userId) {
  const supabase = createClient(...)
  
  try {
    // 1. wrong_notes 저장
    const { data: note, error: noteError } = await supabase
      .from('wrong_notes')
      .insert({
        user_id: userId,
        exam_type: 'toeic',
        part: noteData.part,
        lc_or_rc: noteData.lcOrRc,
        question_number: noteData.questionNumber,
        question: noteData.question,
        answer: noteData.answer,
        explanation: noteData.explanation,
        difficulty: noteData.difficulty,
        solving_time: noteData.solvingTime,
        wrong_reason: noteData.wrongReason,
        auto_tags: noteData.autoTags,
        user_selected_tags: noteData.userSelectedTags,
        source_image_url: noteData.sourceImageUrl,
        // Part 1
        image_trap_type: noteData.imageTrapType,
        keyword_missed: noteData.keywordMissed,
        passive_voice_error: noteData.passiveVoiceError,
        // Part 2
        question_pattern: noteData.questionPattern,
        answer_type: noteData.answerType,
        // Part 3
        set_position: noteData.setPosition,
        preview_read: noteData.previewRead,
        // Part 4
        lecture_type: noteData.lectureType,
        note_taking: noteData.noteTaking,
        // Part 5
        grammar_category: noteData.grammarCategory,
        grammar_sub_type: noteData.grammarSubType,
        // Part 6
        blank_type: noteData.blankType,
        context_fail_reason: noteData.contextFailReason,
        // Part 7
        passage_type: noteData.passageType,
        question_type: noteData.questionType,
        timeout_flag: noteData.timeoutFlag,
      })
      .select()
      .single()
    
    if (noteError) throw noteError
    
    // 2. users.usage_count 증가
    const { error: userError } = await supabase.rpc('increment_usage', {
      user_id: userId
    })
    
    if (userError) throw userError
    
    // 3. score_analytics 업데이트 (백그라운드)
    // tag_stats는 뷰라서 자동 계산됨
    
    return { success: true, noteId: note.id }
    
  } catch (error) {
    console.error('저장 실패:', error)
    
    // 로컬 임시 저장 (오프라인 대응)
    localStorage.setItem(
      `pending_note_${Date.now()}`,
      JSON.stringify(noteData)
    )
    
    throw error
  }
}
```

**Supabase RPC 함수 (SQL):**
```sql
CREATE OR REPLACE FUNCTION increment_usage(user_id UUID)
RETURNS void AS $$
BEGIN
  UPDATE users 
  SET usage_count = usage_count + 1,
      updated_at = NOW()
  WHERE id = user_id;
END;
$$ LANGUAGE plpgsql;
```

**구현 로직:**

```javascript
function calculateDailyScore(userId) {
  // 1. 최근 7일 오답 데이터 수집
  const recent7Days = getRecentWrongNotes(userId, 7)
  
  // 2. 일별 정확도 계산
  const dailyAccuracy = recent7Days.map(day => ({
    date: day.date,
    accuracy: 1 - (day.wrongCount / day.totalCount)
  }))
  
  // 3. 추세선 분석 (선형 회귀)
  const trend = linearRegression(dailyAccuracy)
  
  // 4. 예상 점수 계산
  const baseScore = user.currentScore
  const improvement = trend.slope * 30  // 30일 후 예상 상승폭
  const estimatedScore = baseScore + improvement
  
  // 5. 약간의 랜덤성 추가 (심리 자극)
  const randomBoost = Math.random() * 5 - 2  // -2 ~ +3 랜덤
  
  return Math.round(estimatedScore + randomBoost)
}
```
