## 토답(Todap) 사이트맵/폴더구조 정리 (Vercel 배포 기준)

> 기준 리포: `/toeai-app` (Vite + React Router + Supabase)  
> 목적: ChatGPT/Claude로 “전반적인 UX 위치 재설계”를 하기 위한 **현 구조 지도(IA + 코드 위치)** 정리

---

## 0) 한눈에 보는 사용자 여정(현재 UX 흐름)

- **(비로그인 유입)** 랜딩 → 로그인 → 무료 진단(옵션) → 홈(오답 등록 시작)
- **(오답 등록)** 홈 하단 카메라 → 이미지 분석(Edge Function) → 확인/수정 모달 → 저장(RPC) → 홈/대시보드/통계 갱신
- **(전략/진행)** 대시보드(Top3/로드맵) ↔ 전략(D-day 압축) ↔ 프로그램(시험일 기반 플랜) ↔ 통계(약점/세부 분포)
- **(결제)** 무료 체험(7일/5문항) 소진 시 배너/모달/업그레이드 → 설정의 `구독·결제` 탭에서 결제 시트 오픈 → PortOne 결제 → 성공 리다이렉트/검증

## 1) 최상위 라우팅 구조 (`toeai-app/src/App.jsx`)

### A. 퍼블릭(비로그인 가능) 라우트

- `/landing` : 랜딩 메인
- `/900-jump` : 랜딩 상세(900 점프)
- `/terms` `/privacy` `/refund-policy` `/contact` `/faq` `/about` : 정책/정보 페이지

### B. 어드민 라우트

- `/admin` (중첩)
  - `/admin`(index) / `/admin/reviews` : 리뷰 관리 패널
  - `/admin/kpi` : KPI 대시보드

### C. 앱 라우트(공통 레이아웃 하위) — `Layout` 아래에 렌더

- `/` : 홈(로그인 상태에 따라 HomeOrLanding에서 분기)
- `/note/:id` : 오답 상세(복습/수정)
- `/dashboard` : 대시보드(요약/Top3/로드맵/그래프)
- `/stats` : 통계(약점/분포/세부)
- `/strategy` : D-day 압축 전략(분석/유료)
- `/program` : 시험일 기반 전략 플랜(진행/압축 모드)
- `/settings` : 설정(내 정보 / 구독·결제)
- `/reviews` : 후기 목록
- `/week/:weekNumber` : 주차/구간 화면(진행 단계)
- `/report/:weekNumber` : 리포트 화면(PDF 등)
- `/upgrade` : 업그레이드 안내(무료 체험 종료 등)

### D. 결제 결과 라우트 (Layout 밖)

- `/payment/success` : PortOne 리다이렉트 성공 후 서버 검증
- `/payment/fail` : 결제 실패 페이지

## 2) 하단 탭(메인 네비게이션) 구조 (`toeai-app/src/components/Layout.jsx`)

레이아웃 하단 탭 5개:

- **홈**: `/`
- **대시보드**: `/dashboard` (및 `/week/*`, `/report/*`도 대시보드 탭 활성 처리)
- **약점**: `/stats`
- **전략**: `/strategy`
- **설정**: `/settings`

추가로, `Layout`에서 전역적으로 아래 UX를 “항상” 품고 있음:

- **무료 체험 배너(상단)**: 무료 체험 종료 시 `결제하기 → /settings?pay=1`로 유도
- **카메라 버튼(홈에서만)**: 오답 등록 진입점
- **AI 분석/확인 모달**: 이미지 분석 결과 확인/수정 → 저장
- **PaywallModal**: 무료 제한(만료) 도달 시 결제 유도

## 3) 페이지(UX 화면)별 “무슨 기능이 어디에 있나”

아래는 “UX 재설계 시 화면 위치를 옮길 때” 가장 많이 건드릴 단위들입니다.

### 3.1 홈(오답노트 허브) — `src/pages/HomePage.jsx`

- **역할**
  - “최근 오답 3개 + 전체 오답 리스트”를 보여주는 메인 허브
  - 파트/태그/클리어 상태 필터 제공
  - 대시보드 요약에서 “오늘 추천 미션/코치 한 줄”을 끌어와 상단 메시지로 사용
- **데이터**
  - `fetchWrongAnswers(userId)`로 오답 리스트 로드
  - `getDashboardSummary(userId)`로 미션/약점 Top3 등을 함께 로드
- **연결되는 주요 컴포넌트/서비스**
  - 카메라 버튼(전역): `src/components/CameraButton.jsx` → `analyzeToeicImage` 호출 흐름

### 3.2 진단(무료 점수 진단 위자드) — `src/pages/DiagnosticPage.jsx`

- **역할**
  - 멀티 스텝 설문형 진단(현재 점수/목표/시험일/약점/공부패턴)
  - 진단 결과 저장 + (조건부) 프로그램 자동 시작
- **저장/연동**
  - `updateUserProfile`, `updateExamDate`
  - `diagnostic_sessions` insert
  - 첫 진단 후 `startProgramV403` 시도(이미 시작했으면 스킵)

### 3.3 대시보드(코칭 홈) — `src/pages/DashboardPage.jsx`

- **역할**
  - 예상 점수/목표 점수/진행률 + Top3 약점 + 로드맵 + 점수 변화
  - ScoreBand 전략 카드(점수대별 조언), One-line 조언 노출
- **데이터**
  - `programService.getDashboardSummary(userId)` 중심

### 3.4 통계(약점/세부 분포) — `src/pages/StatsPage.jsx`

- **역할**
  - 파트 분포, 태그 TOP, 세그먼트(Part5/Part7/Part2/시간부족) 분석
  - 유료/무료에 따라 상세 블록 노출 차등
- **데이터**
  - `fetchTagStats`, `fetchSegmentStats`, `getSubscription`, `getUserProfile`

### 3.5 전략(D-day 압축 전략) — `src/pages/StrategyPage.jsx`

- **역할**
  - 시험일까지 남은 일수로 **모드(일반/압축/고압축/생존)** 표시
  - 유료 사용자일 때 `analyzeStrategy`로 AI 전략 분석 결과 노출
- **결제 유도**
  - 비구독 시 `설정에서 구독하기 → /settings?pay=1`

### 3.6 프로그램(시험일 기반 전략 플랜) — `src/pages/ProgramPage.jsx`

- **역할**
  - 시험일 기반 전략 플랜 진행(블록/압축 모드 UI 포함)
  - 주차(구간) 진행, 리포트 조회/표시
- **압축 플랜**
  - `programService.buildCompressedPlan(plans, examDate)`로 뷰 모델 생성
- **결제 유도**
  - Pro 필요 액션은 `'/settings?pay=1'`로 연결

### 3.7 설정(내 정보 / 구독·결제) — `src/pages/SettingsPage.jsx`

- **탭(현재: 2탭)**
  - 내 정보: 계정, 점수 입력, 시험일 입력, 앱 정보
  - 구독·결제: 구독 현황, 결제 시트(플랜 선택), 서비스 정책 링크, 사업자 정보
- **결제 진입 파라미터**
  - `/settings?pay=1`로 진입하면 **구독 탭 활성화 + 결제 시트 자동 오픈**

### 3.8 업그레이드(체험 종료) — `src/pages/UpgradePage.jsx`

- **역할**
  - 무료 체험 종료/플랜 종료 시 업그레이드/연장 유도
  - 결제 진입은 `'/settings?pay=1'`

## 4) 결제(PortOne) UX/로직 위치

### 4.1 결제 UI

- 결제 플랜 바텀시트: `src/components/PaymentSheet.jsx`
  - 플랜 카드(15/30/60일), 동의 체크, **휴대폰 번호 입력(이니시스 V2 필수)**
  - 결제 호출: `requestPlanPayment(planKey, { customerEmail, customerName, customerPhone })`
- 무료 제한 도달 결제 유도 모달: `src/components/PaywallModal.jsx`
  - 플랜 선택 → 결제 호출(휴대폰 번호 없으면 prompt)
- 전역 배너/모달 트리거: `src/components/Layout.jsx`
  - 무료 체험 종료 배너의 CTA: `'/settings?pay=1'`

### 4.2 결제 요청/검증 서비스

- `src/services/portonePayment.js`
  - `requestPlanPayment`: PortOne V2 `requestPayment` 호출
    - Inicis V2 일반 결제 대응: `customer.phoneNumber` 포함 필수
  - `verifyPortonePayment`: Supabase Edge Function `verify-portone-payment` 호출(서버 검증)
- 결제 성공 처리: `src/pages/PaymentSuccessPage.jsx`
  - URL 파라미터(`paymentId`, `plan`) 기반 검증 호출 → 성공 시 `/program` 이동

## 7) UX 재설계에 바로 쓰는 “이동/유도 포인트” 체크리스트

- **결제 유도 CTA는 모두 `/settings?pay=1`로 통일**되어 있는가?
  - 배너/업그레이드/전략/프로그램 등
- **오답 등록의 시작점이 홈 탭 1곳에만 있는지**(카메라 버튼)
  - 다른 화면에도 보조 CTA를 둘지 결정 가능
- **‘대시보드 vs 홈 vs 전략’ 메시지가 중복되는지**
  - 미션/코치 멘트/Top3 같은 정보가 여러 화면에 분산되어 있음
- **정책/사업자 정보가 결제 탭에 포함되어 있음**
  - 결제 전 “신뢰 요소”로 배치되어 있음(현재는 구독·결제 탭 하단)
