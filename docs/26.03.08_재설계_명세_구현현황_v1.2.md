### B. PortOne V2 서버사이드 결제 검증

**보안 문제 해결:** 클라이언트에서 직접 `setSubscriptionPlan()` 호출 → 결제 위조 가능. Edge Function으로 완전 대체.

**흐름:**
```
앱(requestPayment) → PortOne SDK → PortOne 결제창
  ↓ 완료 후
PaymentSuccessPage(?paymentId=...&plan=...)
  ↓
verifyPortonePayment() → Supabase Edge Function
  ↓
PortOne REST API GET /payments/{paymentId}
  ↓ 검증: status=PAID + amount 일치
subscriptions.upsert(expires_at = now + N days) + payments.insert
```

**구현 파일:**
- `supabase/functions/verify-portone-payment/index.ts` — Edge Function
  - JWT 인증 → 중복 paymentId 체크 → PortOne API 호출 → 금액/상태 검증 → subscriptions/payments upsert
- `src/pages/PaymentSuccessPage.jsx` — Toss 파라미터(`paymentKey/orderId`) → PortOne 파라미터(`paymentId/plan/code`) 전환
- `src/services/portonePayment.js` — `verifyPortonePayment(paymentId, userId, plan)` 함수

**배포 체크리스트:**
```bash
# Supabase Secrets 설정 (대시보드 → Project Settings → Edge Functions → Secrets)
PORTONE_API_SECRET = <포트원 V2 REST API 시크릿>

# Edge Function 배포
supabase functions deploy verify-portone-payment

# .env.local 확인
VITE_PORTONE_STORE_ID=your_store_id
VITE_PORTONE_CHANNEL_KEY=your_channel_key
```

- auto_score: `user_tag_stats` 기반 실시간 계산 (DB 저장 안 함)
- user_override: `user_mastery_status` 테이블에만 저장

**Status 판정:**
```
attempts < 3         → not_started
auto_score ≥ 75 & attempts ≥ 5 → mastered
auto_score ≥ 55      → stabilizing
else                 → in_progress
user_override = needs_review → recheck (강제)
```

**user_override 3가지:** `uncertain` (아직 불안해요) / `confident` (어느 정도 잡았어요) / `needs_review` (다시 봐야 해요)
