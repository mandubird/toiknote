# 후기와결제전환_프롬포트.md

## 문서 목적
토답(todap.kr)의 후기 시스템을 단순 후기 모음이 아니라 **결제 전환을 높이는 장치**로 설계하고,  
동시에 UX/UI 측면에서 **후기 노출 위치, 수집 흐름, CTA 연결 구조**까지 개선하기 위한 통합 프롬프트 문서.

이 문서는 2가지 용도로 사용한다.

1. **기획 기준 문서**
2. **클로드 / 커서AI에 전달할 실행 프롬프트**

---

# 1. 핵심 배경

토답은 충동구매형 서비스가 아니다.  
사용자는 결제 전 아래를 의심한다.

- 진짜 점수 향상에 도움이 되는가?
- 내 상황에도 맞는가?
- 헛공부를 줄여주는가?
- 돈보다 시간이 아깝지 않은가?

즉, 토답의 핵심 병목은 단순 가격이 아니라 **신뢰와 효과 증명**이다.

그래서 후기 시스템은 단순히 “고객 의견을 받는 기능”이 아니라 아래 목적을 가져야 한다.

### 후기 시스템의 3가지 목적
1. **결제 전 불안 해소**
2. **나와 비슷한 사람 사례 제공**
3. **결제 직전 마지막 전환 압력 제공**

---

# 2. 핵심 원칙

## 2-1. 후기 = 게시판이 아니라 전환 자산
토답은 자유게시판형 후기보다 **구조화된 사례 카드형 후기**가 더 적합하다.

이유:
- 게시판은 산만하다
- 품질 편차가 크다
- 구매 전 신뢰 형성에 약하다
- 핵심 정보(시작 점수, 목표 점수, 사용 기간, 약점, 체감 변화)가 한눈에 안 보인다

따라서 후기 영역은 “후기 게시판”이 아니라 아래처럼 설계한다.

### 추천 명칭
- 점수 상승 사례
- 실제 사용자 후기
- 비슷한 사용자 사례
- 사용자 변화 기록
- 토답 후기

### 가장 추천하는 명칭
**점수 상승 사례**

---

# 3. 후기 시스템 전체 구조

후기 시스템은 아래 4단계로 설계한다.

## 3-1. 수집
후기를 받는 타이밍과 조건을 설계한다.

## 3-2. 정제
짧은 피드백 → 공개 가능한 후기 카드로 전환한다.

## 3-3. 노출
결제 전환이 일어나는 위치에 전략적으로 배치한다.

## 3-4. 보상
후기 작성에 대한 동기를 제공한다.

---

# 4. 후기 수집 설계

## 4-1. 후기 요청 타이밍
고정적으로 “7일 후”만 띄우지 말고, **시간 + 사용량 조건**을 같이 본다.

### 후기 요청 트리거 추천
아래 중 하나 이상 충족 시 후기 요청 팝업/모달 표시

- 첫 결제 후 5~7일 경과
- 오답 10개 이상 등록
- 전략 분석 2회 이상 실행
- 오늘 할 공부 3개를 3일 이상 확인
- 시험 D-14 진입
- 시험 D-7 진입

즉, “시간이 지났기 때문”만이 아니라  
**사용자가 가치를 체감했을 가능성이 높은 시점**에 요청한다.

---

## 4-2. 후기 수집 방식
처음부터 긴 후기 작성 폼을 띄우지 않는다.  
2단계 방식으로 간다.

### 1차: 초간단 피드백
목표: 진입장벽 낮추기

질문 예시:
- 토답이 도움됐나요?
- 가장 도움된 기능은 무엇이었나요?
- 한 줄로 표현하면 어땠나요?

선택형 예시:
- 공부 방향이 정리됨
- 약점이 명확해짐
- Part7 시간 전략에 도움됨
- 무엇을 해야 할지 알게 됨
- 생각보다 별로였음
- 아직 잘 모르겠음

주관식 예시:
- 한 줄로 남겨주세요

---

### 2차: 공개용 후기 확장
1차 응답 중 좋은 사례만 확장 질문

질문 예시:
- 시작 점수
- 목표 점수
- 사용 기간 (15일 / 30일 / 60일)
- 가장 큰 약점
- 가장 도움된 기능
- 실제 달라진 점
- 공개 동의 여부

---

# 5. 후기 보상 설계

## 5-1. 핵심 원칙
“좋은 후기”를 써야 보상을 주면 안 된다.  
그렇게 하면 후기 신뢰도가 깨진다.

보상 기준은:
**긍정 후기 작성**이 아니라  
**성실한 피드백/후기 제출 완료**여야 한다.

---

## 5-2. 추천 보상안
### 베타 초기 추천
- 후기/피드백 제출 시 3일 연장
- 후기/피드백 제출 시 5일 연장
- 심화 전략 분석 1회 추가 제공
- PDF 리포트 1회 추가 제공

### 가장 추천하는 초기안
**피드백 제출 시 5일 연장 또는 전략 분석 1회 추가**

이유:
- 현금 할인보다 자연스럽다
- 서비스 가치와 연결된다
- 베타 사용자에게 동기 부여가 된다

---

# 6. 후기 노출 구조

후기를 한 군데에만 모아두면 약하다.  
**결제 전환이 일어나는 구간마다 나눠서 심어야 한다.**

## 6-1. 가장 중요한 노출 위치

### A. 결제 페이지 바로 위
가장 중요하다.

목적:
- 결제 직전 불안 제거
- “나랑 비슷한 사람도 효과를 봤다”는 신뢰 형성

구성:
- 짧은 후기 2~3개
- 시작 점수 / 목표 점수 / 사용 기간 / 한 줄 체감
- 바로 아래 CTA 버튼

예시:
- 815 → 목표 900 / 30일 사용  
  “무작정 공부하던 걸 멈추고, 뭘 먼저 해야 할지 정리됐어요.”
- 780 → 845 / 15일 사용  
  “시험 직전에 뭘 버리고 뭘 해야 할지 딱 정해져서 좋았어요.”

버튼:
- 15일 시작하기
- 30일 시작하기
- 60일 시작하기

---

### B. 홈/대시보드 중간
목적:
- “나만 쓰는 서비스가 아니다” 인식 제공
- 서비스 신뢰도 강화

예시 섹션명:
- 비슷한 사용자 사례
- 점수 상승 사례
- 실제 사용자 후기

---

### C. 전략 페이지 내부
목적:
- 현재 내 전략과 비슷한 사례를 보여줘 설득 강화

예시:
- Part7 시간 부족 사례
- 800후반 정체 사례
- 시험 2주 전 압축 사례

즉, 사용자 상태에 맞는 후기 노출이 중요하다.

---

### D. 랜딩페이지 중상단
목적:
- “실제 변화가 있는 서비스”라는 첫인상 형성

예시 문구:
- 실제 사용자 후기 12개
- 점수 상승 사례 7개
- 850 정체 구간 사례 다수 확보

---

# 7. 후기 카드 구조

후기는 자유 텍스트보다 **카드형 구조화**가 중요하다.

## 추천 카드 필드
- 시작 점수
- 목표 점수
- 사용 기간
- 가장 큰 약점
- 가장 도움된 기능
- 한 줄 후기
- 달라진 점
- 추천 대상 유형

---

## 카드 예시 1
- 시작 점수: 815
- 목표 점수: 900
- 사용 기간: 30일
- 가장 큰 약점: Part7 시간 부족 / 문장구조
- 가장 도움된 기능: 오늘 해야 할 공부 3개
- 한 줄 후기: 무작정 공부하던 걸 멈추고, 뭘 먼저 해야 할지 알게 됐어요.
- 달라진 점: 오답 정리 기준이 생기고 공부 루틴이 덜 흔들렸어요.

---

## 카드 예시 2
- 시작 점수: 780
- 목표 점수: 850
- 사용 기간: 15일
- 가장 큰 약점: 문법 / 시간 부족
- 가장 도움된 기능: 전략 분석
- 한 줄 후기: 시험 직전 압축 공부할 때 진짜 유용했어요.
- 달라진 점: 파트별로 뭘 버리고 뭘 챙겨야 하는지 정리됐어요.

---

# 8. 후기 분류/필터 설계

후기 수가 쌓이면 아래 기준으로 필터링 가능하게 한다.

## 추천 필터
- 700 → 800대
- 800 → 900대
- 850 정체
- 시험 2주 전
- Part7 시간 부족
- 문장구조 약점
- 문법 약점
- 전략 정리형 후기
- 점수 상승형 후기

핵심:
사용자가 “나와 비슷한 사람”을 빨리 찾을 수 있어야 한다.

---

# 9. 후기 유형 우선순위

초기에는 점수 상승 후기만 기다리면 느리다.  
그래서 후기 우선순위를 이렇게 본다.

## 1순위: 전략 명확화형
예:
- 무엇을 해야 할지 몰랐는데 정리됐다
- 공부 방향이 잡혔다
- 헛공부가 줄었다

## 2순위: 루틴 교정형
예:
- 오답 정리가 쉬워졌다
- 공부 우선순위가 보였다
- Part7 시간을 어떻게 써야 할지 감이 왔다

## 3순위: 점수 상승형
예:
- 815 → 865
- 850 → 900

즉 초반에는 **체감 후기부터 확보**하고,  
점수 상승 후기는 중장기적으로 누적시킨다.

---

# 10. 결제 전환과의 연결 방식

후기가 실제 매출로 이어지려면 아래가 필요하다.

## 10-1. 후기 아래 바로 CTA 배치
후기 보고 끝나면 안 된다.

예시:
- 이 사례와 비슷하다면 30일 코칭 시작하기
- 시험 2주 전이라면 15일 압축 코칭 시작하기
- 850 정체라면 60일 정체 탈출 시작하기

---

## 10-2. 후기와 상품 연결
각 후기에는 어떤 상품이 적합한지 자연스럽게 연결한다.

예:
- 시험 임박 후기 → 15일 추천
- 일반 학습 루틴 후기 → 30일 추천
- 장기 정체 탈출 후기 → 60일 추천

---

## 10-3. 사용자의 상태 기반 매칭
가능하면 사용자의 상태에 맞는 후기 우선 노출

예:
- 사용자가 목표 900 입력 → 800후반 정체 후기 우선 노출
- 시험 D-10 → 15일 압축 후기 우선 노출
- Part7 약점 많음 → Part7 시간 부족 후기 우선 노출

---

# 11. UX/UI 개선 방향

후기 시스템은 단순 기능 추가가 아니라,  
UX 흐름 전체 안에서 결제 전환 장치로 작동해야 한다.

## 11-1. UX 원칙
- 후기 모음이 아니라 **증거 레이어**
- 게시판이 아니라 **사례 라이브러리**
- 리뷰 텍스트가 아니라 **구조화된 카드**
- 후기 보기로 끝나지 않고 **결제로 연결**

---

## 11-2. UI 원칙
- 후기 카드는 정보 밀도가 높지만 읽기 쉬워야 함
- “시작 점수 / 목표 점수 / 사용 기간”은 상단 고정
- 한 줄 후기는 크게
- CTA 버튼은 카드 하단 또는 섹션 하단 배치
- 후기 섹션은 본문 카드와 시각적으로 구분되는 톤 사용

---

# 12. 개발 우선순위

## 1단계
- 후기 요청 팝업 추가
- 1차 짧은 후기 수집 폼
- 후기 제출 시 보상 지급 로직
- 후기 데이터 저장 구조 설계

## 2단계
- 점수 상승 사례 페이지 제작
- 카드형 후기 리스트 제작
- 후기 카드 필터 기능 추가

## 3단계
- 결제 페이지 후기 고정 노출
- 전략 페이지에 상태별 후기 추천 노출
- 홈/대시보드에 사례 미리보기 삽입

## 4단계
- 후기 기반 자동 추천 고도화
- 사용자 상태별 후기 매칭
- 후기 콘텐츠를 마케팅 자산으로 외부 활용

# 13. 클로드용 통합 프롬프트

아래 프롬프트를 클로드에 그대로 넣어 UX/기획 재설계를 받는다.

---

## 클로드 프롬프트 시작

토답(todap.kr)은 토익 점수가 안 오르는 이유를 분석하고, 오늘 무엇을 공부해야 하는지 알려주는 AI 코칭 서비스다.

현재 나는 토답의 후기 시스템을 단순 후기 모음이 아니라, 실제 결제 전환을 높이는 핵심 장치로 만들고 싶다.

중요한 전제는 아래와 같다.

1. 토답은 충동구매형 서비스가 아니다.
2. 사용자는 결제 전에 “진짜 점수 향상에 도움이 되는가?”를 가장 크게 의심한다.
3. 그래서 후기의 핵심 목적은 단순 만족도 표시가 아니라, 신뢰 형성과 결제 전환 유도다.
4. 후기 시스템은 게시판형보다 구조화된 사례 카드형이 더 적합하다.
5. 점수 상승 후기만이 아니라, “공부 방향이 잡혔다 / 헛공부가 줄었다 / 약점이 명확해졌다” 같은 전략 체감 후기도 매우 중요하다.
6. 후기 요청은 단순 시간 경과가 아니라, 사용량과 가치 체감 시점을 함께 고려해야 한다.
7. 후기 작성 보상은 “좋은 후기”가 아니라 “성실한 피드백 제출”에 주어져야 한다.

내가 원하는 것은 아래 6가지다.

1. 토답 후기 시스템 전체 UX 구조 설계
2. 후기 요청 타이밍/트리거 설계
3. 후기 작성 플로우(짧은 피드백 → 공개 후기 전환) 설계
4. 후기 보상 정책 설계
5. 후기 노출 위치별 결제 전환 UX 설계
6. 후기 페이지/사례 페이지 정보 구조와 카피 방향 제안

추가 요구사항:
- 게시판형보다 카드형 사례 라이브러리 중심으로 설계해줘
- 결제 직전 페이지, 홈, 전략 페이지 각각 어떤 후기 유형을 노출해야 할지 나눠서 제안해줘
- 사용자 상태(시험 임박, 850 정체, Part7 시간 부족 등)에 맞는 후기 추천 구조도 제안해줘
- 후기 섹션 이름, CTA 문구, 후기 카드 구조 예시도 함께 제안해줘
- 모바일 퍼스트 기준으로 설명해줘
- 실제 서비스에 바로 반영 가능한 수준으로 구체적으로 작성해줘

출력 형식:
1. 문제 진단
2. 후기 시스템 목표
3. UX 구조 제안
4. 후기 수집 플로우
5. 후기 보상 구조
6. 노출 위치별 전환 설계
7. UI/카피 예시
8. 구현 우선순위

# 14. 커서AI용 구현 프롬프트

## 커서AI 프롬프트 시작

현재 토답(todap.kr)에 후기 시스템을 새로 추가하려고 한다.

목표는 단순 후기 게시판이 아니라, 결제 전환을 높이는 “점수 상승 사례” 시스템을 만드는 것이다.

다음 요구사항을 반영해 프론트엔드와 필요한 상태 흐름을 설계/구현해줘.

### 목표
- 후기 작성 유도
- 후기 카드형 사례 페이지 제작
- 결제 페이지/홈/전략 페이지에 후기 노출
- 후기와 결제 CTA 연결
- 모바일에서 보기 좋은 정보 위계 구성

### 후기 수집 기능
1. 후기 요청 모달/팝업
2. 트리거 조건 예시:
   - 첫 결제 후 5~7일
   - 오답 10개 이상 등록
   - 전략 분석 2회 이상
   - 오늘 할 공부 3개를 3일 이상 확인
3. 1차 짧은 피드백 폼
   - 도움됐나요?
   - 가장 도움된 기능은?
   - 한 줄 후기
4. 2차 공개 후기 확장 폼
   - 시작 점수
   - 목표 점수
   - 사용 기간
   - 가장 큰 약점
   - 가장 도움된 기능
   - 달라진 점
   - 공개 동의 여부

### 보상 기능
- 후기/피드백 제출 시 5일 연장 또는 전략 분석 1회 추가
- “좋은 후기” 여부와 무관하게 제출 완료 기준으로 보상 처리
- 보상 안내 UI 포함

### 후기 노출 기능
1. 점수 상승 사례 페이지
   - 카드 리스트 형태
   - 필터:
     - 700→800대
     - 800→900대
     - 850 정체
     - 시험 2주 전
     - Part7 시간 부족
     - 문장구조
     - 문법 약점
2. 결제 페이지 상단 또는 중단
   - 후기 2~3개 요약 카드
   - 바로 아래 CTA 버튼
3. 홈/대시보드
   - 사례 미리보기 섹션
4. 전략 페이지
   - 현재 사용자 상태와 유사한 후기 추천 섹션

### UI 요구사항
- 게시판 느낌 금지
- 카드형 사례 라이브러리로 구성
- 시작 점수 / 목표 점수 / 사용 기간을 상단에 잘 보이게
- 한 줄 후기는 크게
- CTA는 후기 섹션 아래에 명확히 배치
- 모바일 퍼스트
- 여백, 계층, 구분감 확실하게
- 너무 템플릿처럼 보이지 않게 토답 서비스 톤에 맞게 정리

### 원하는 산출물
1. 컴포넌트 구조 제안
2. 필요한 상태값/데이터 구조 제안
3. UI 리팩토링 방향
4. 실제 구현 코드 초안
5. 후기 카드 컴포넌트 예시
6. 후기 요청 모달 예시
7. 결제 CTA 연결 방식 제안

현재 코드베이스를 최대한 활용하되, 정보 위계와 전환 흐름이 더 좋아지도록 개선해줘.

# 15. 최종 한 줄 정리

토답의 후기는 장식이 아니라 **결제 전환 장치**다.  
따라서 자유게시판형이 아니라 **구조화된 점수 상승 사례 시스템**으로 설계하고,  
후기 수집 → 보상 → 사례 카드화 → 결제 버튼 연결까지 하나의 전환 흐름으로 만들어야 한다.
