# 토답 KPI 대시보드 + Supabase 연동 반자동 관리 구조 v2

## 0. 목적

이 문서는 토답 1기 서포터즈 운영 전에  
KPI 대시보드와 Supabase 운영 구조를 **실제 실행 가능한 상태로 점검하고**,  
서포터즈 운영 데이터가 대시보드에 제대로 반영되도록 만드는 최신 기준 문서다.

핵심 목표:
1. KPI 필드가 실제 DB에 존재하는지 사전 검증
2. 관리자 플랜 부여 페이지를 우선 구현
3. 서포터즈 운영 데이터를 Supabase 기준으로 반자동 관리
4. KPI 대시보드가 “실제 행동 데이터”를 기준으로 작동하게 만들기

---

## 1. 지금 당장 실행 전에 반드시 확인할 것 2개

### 1-1. KPI 필드가 DB에 실제로 존재하는가?
문서에만 있고 Supabase 테이블에 실제 컬럼이 없으면  
서포터즈 운영 시작 후 데이터가 쌓이지 않는다.

반드시 확인할 필드:
- `first_login_at`
- `first_wrong_note_at`
- `first_coaching_view_at`
- `activated_at`
- `day3_active_at`
- `day7_active_at`
- `review_submitted`
- `review_public_allowed`
- `score_change_reported`
- `recommendation_intent`

### 왜 중요한가
서포터즈 운영은 기간이 짧다.  
운영 시작 후에 “이 필드 안 만들었네”를 발견하면  
첫날 활성화율 / 3일 사용률 / 후기율을 놓치게 된다.

### 실행 체크
- Supabase SQL Editor에서 컬럼 확인
- 없으면 migration 먼저 생성
- 이벤트가 실제 update/insert 되는지 테스트 유저로 검증

---

### 1-2. 관리자 플랜 부여 페이지가 아직 없는가?
없다면 **이번 주 실행 전 유일한 필수 개발 작업**이다.

이유:
- SQL 직접 입력은 실수 가능성 높음
- 플랜 지급 타이밍이 늦어지면 서포터즈 열기가 식음
- 9명은 버틸 수 있어도, 반복 운영 시 병목이 됨

### 결론
- `/admin/supporters` 또는 `/admin/grant-plan` 페이지를 먼저 만든다
- 최소 기능만 있어도 충분하다
- 반나절 수준 작업으로 우선 구현 가능

---

## 2. 현재 운영 구조의 핵심 변화

기존:
- 베타테스터
- 긴 신청폼
- 수동 운영 중심
- 설명형 데이터 구조

변경:
- 서포터즈
- 9문항 신청폼
- 반자동 플랜 지급
- 행동 기반 KPI 중심

즉 지금은:
> “많은 정보 수집”보다 “빠른 선발 → 빠른 첫 코칭 → 행동 데이터 확보”가 중요하다.

---

## 3. 최신 운영 원칙

### 원칙 1
신청 단계는 최대한 짧게  
→ 9문항 신청폼 기준

### 원칙 2
선발 후 즉시 플랜 부여  
→ 관리자 페이지로 처리

### 원칙 3
첫날 코칭 확인이 가장 중요한 KPI  
→ activation의 시작점

### 원칙 4
Google Sheet는 운영 참고용,  
Supabase는 KPI 기준 DB

- 후기 / 공개 동의 / 점수 변화

> Sheet는 임시 운영 도구, Supabase는 진짜 기준 DB

## 10. SQL / 데이터 반영 예시

### 10-1. supporters_ops insert
```sql
insert into supporters_ops (
  user_id,
  cohort_name,
  supporters_group,
  is_selected,
  selected_at,
  plan_type,
  plan_start_at,
  plan_end_at,
  admin_granted_at,
  admin_granted_by
)
values (
  'USER_ID',
  'supporters_1st',
  '30d',
  true,
  now(),
  'supporters_30d',
  now(),
  now() + interval '30 days',
  now(),
  'admin@example.com'
);
```

---

### 10-2. 후기 제출 update
```sql
update supporters_ops
set
  review_submitted = true,
  review_public_allowed = true,
  updated_at = now()
where user_id = 'USER_ID';
```

---

### 10-3. 점수 변화 반영
```sql
update supporters_ops
set
  score_change_reported = true,
  score_before = 835,
  score_after = 890,
  updated_at = now()
where user_id = 'USER_ID';
```
