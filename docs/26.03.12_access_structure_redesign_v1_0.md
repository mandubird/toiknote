# 1. 현재 구조의 문제 정의

현재 `todap.kr` 접속 시 노출되는 화면은
랜딩페이지가 아니라 앱 내부 홈처럼 보이는 구조다.

예시:
- 오늘 등록 0개
- 미완료 0개
- 가장 취약 -
- 오늘 추천 미션
- 아직 오답이 없어요
- 카메라 버튼을 눌러 첫 오답을 등록해보세요

이 화면은 기존 사용자에게는 어느 정도 맞을 수 있지만,
신규 방문자에게는 다음과 같은 문제를 만든다.

## 1.1 첫인상이 “앱 내부”처럼 보인다
신규 사용자는 아직 서비스 가치도 모르고,
왜 써야 하는지도 모르는 상태다.
그런데 첫 화면이 이미 로그인된 사용자용 빈 홈처럼 보이면
“이게 뭐 하는 서비스인지” 이해하기 어렵다.

## 1.2 랜딩페이지가 숨어 있다
현재 랜딩페이지는 우측 상단의 텍스트 메뉴(예: 900점프) 등을 통해 접근하는 구조로 보인다.
이 방식은 신규 유입 기준으로 랜딩이 거의 메인 동선에 들어오지 못한다.

즉, 현재 구조는 아래처럼 되어 있다.

```text
todap.kr
→ 앱 같은 화면
→ 사용자가 랜딩을 따로 찾아가야 함
```

하지만 실제로는 이렇게 되어야 한다.

```text
todap.kr
→ 랜딩페이지
→ 무료 진단
→ 무료 체험
→ 유료 결제
→ 앱 사용
```

## 1.3 현재 홈 화면은 “가치 제안”보다 “행동 지시”가 강하다
현재 홈은
- 카메라 버튼 눌러라
- 오답 등록해라
- 아직 데이터가 없다

같은 행동 유도는 있지만,
그 전에 필요한 가치 설명이 부족하다.

신규 방문자는 먼저 아래를 알아야 한다.

- 이 서비스는 무엇인가?
- 왜 점수가 안 오르는가?
- 이 서비스가 무엇을 다르게 해주는가?
- 무료로 무엇을 해볼 수 있는가?
- 돈 내면 무엇이 달라지는가?

즉, 현재 구조는 매출과 전환에 불리하다.

# 2. 핵심 결론

현재 `todap.kr`는 앱을 먼저 보여주고 있다.
하지만 토답은 지금 단계에서 아래 퍼널로 가야 매출이 난다.

```text
설득
→ 무료 진단
→ 무료 체험
→ 결제
→ 앱 사용
```

따라서 구조는 아래처럼 바뀌어야 한다.

## 최종 구조
- `todap.kr` = 랜딩페이지
- `todap.kr/diagnostic` = 무료 진단
- `todap.kr/app/*` = 실제 앱 화면
- 앱 화면은 로그인 사용자 중심
- 랜딩은 신규 방문자 중심

즉,
앱을 메인으로 두는 것이 아니라,
랜딩을 메인으로 두고 앱은 하위 서비스 영역으로 분리한다.

# 4. 도메인 및 라우팅 구조 재설계

## 4.1 메인 도메인 역할
### 기존
- `todap.kr` → 앱 홈처럼 보이는 화면

### 변경
- `todap.kr` → 랜딩페이지

## 4.2 앱 하위 경로 분리
### 권장 구조
```text
/                      → 랜딩페이지
/landing               → 랜딩페이지(동일 내용 또는 리다이렉트)
/diagnostic            → 무료 진단 시작
/diagnostic/result     → 무료 진단 결과(선택)
/app/home              → 앱 홈
/app/dashboard         → 대시보드
/app/weakness          → 약점
/app/strategy          → 전략
/app/settings          → 설정
/login                 → 로그인
/signup                → 회원가입
/pricing               → 가격표(선택)
```

## 4.3 리다이렉트 규칙
### 비로그인 사용자가 `/app/*` 접근
- 로그인 페이지로 이동
또는
- 랜딩페이지 + 로그인 유도

### 로그인 완료 후
- redirect 파라미터가 있으면 해당 페이지
- 신규 가입 직후면 `/diagnostic`
- 기존 사용자는 `/app/home`

# 6. 무료 진단과 무료 체험의 연결 구조

무료 진단과 오답 5문제 무료 체험은 같은 기능이 아니다.
둘은 반드시 분리되어야 하며, 순차적으로 연결되어야 한다.

## 6.1 무료 진단의 역할
- 방향 잡기
- 현재 점수 구조 파악
- 시험일까지 전략 모드 계산
- 손실 원인 Top3 미리 보여주기

## 6.2 무료 체험의 역할
- 정밀도 올리기
- 실제 오답 기반 분석
- 태그/파트/LC 원인 보정
- 체크리스트 상태 업데이트

## 6.3 최종 흐름
```text
랜딩
→ 무료 진단
→ 진단 결과
→ 오답 5문제로 진단 정확도 높이기
→ 무료 체험
→ 유료 플랜 전환
```

# 7. 무료 진단 진입 페이지(`/diagnostic`) 설계 개요

## 7.1 목적
랜딩의 “무료 진단” CTA를 실제 기능으로 연결하기 위한 신규 페이지

## 7.2 기본 구조
멀티스텝 폼으로 구성

### Step 1
최근 점수 입력
- 총점
- LC
- RC
- 또는 점수 구간 선택

### Step 2
목표 점수 / 시험일 입력

### Step 3
체감 약점 선택
- Part 5 문법
- Part 5 어휘
- Part 2 우회답변
- LC 집중력/발음
- Part 7 시간 부족
- Part 7 추론/패러프레이즈
- 잘 모르겠음

### Step 4
공부 패턴 선택
- 문제만 많이 품
- 약점은 아는데 정리가 안 됨
- 오답 정리는 하지만 반복
- 시험일까지 계획 없음
- 실전에서 시간 관리 실패

### Step 5
결과 화면
- 현재 예상 점수
- 목표까지 필요한 점수
- 손실 원인 Top3
- 전략 모드
- 첫 번째 추천 액션
- 오답 5문제 체험 CTA

# 8. 로그인/회원가입 흐름 재설계

무료 진단은 계정 기반 데이터로 저장되어야 하므로,
진단 전에 로그인/회원가입이 필요하다.

## 8.1 비로그인 사용자
랜딩 CTA 클릭 시:
- `/login?redirect=/diagnostic`

## 8.2 회원가입 완료 직후
- 신규 가입이면 `/diagnostic`
- 기존 로그인 유저면 redirect path 우선

## 8.3 진단 결과 저장
진단 결과는 두 군데 저장한다.

### users
현재 활성 프로필 저장
- current_score
- lc_score
- rc_score
- target_score
- exam_date
- score_range 등

### diagnostic_sessions
진단 히스토리 저장
- 진단 시점
- 입력값
- 도출 결과
- 이후 비교 가능

즉,
- `users` = 현재 상태
- `diagnostic_sessions` = 기록

# 9. 무료 체험 정책 반영

현재 구독 모델이 아니라
15일 / 30일 / 60일 일회성 결제로 가는 구조를 기준으로 접근 구조를 맞춘다.

## 9.1 무료 체험 정책 정의
- 오답 5문제 무료 체험
- 체험 기간은 별도 설정
- 체험 데이터는 유료 전환 후 그대로 유지

## 9.2 체험 기간 제안
### 권장안
- 5일 또는 7일 체험

### 대안
- 3일 체험도 가능
- 단, **가입 시점이 아니라 첫 오답 등록 시점부터 시작** 권장

## 9.3 체험 상태 표시
앱 홈 또는 상단 배너에 표시
- 남은 무료 체험 문제 수
- 남은 무료 체험 일수

예:
- 무료 체험 3/5문제 사용
- 체험 종료까지 4일 남음

# 10. 앱 홈 역할 재정의

현재 홈 화면은 신규 방문자에게 노출되기엔 부적절하지만,
로그인 사용자에게는 유지 가능하다.

다만 역할을 명확히 해야 한다.

## 10.1 홈의 역할
- 바로 오답 등록
- 오늘의 미션
- 최근 활동

## 10.2 홈에서 보여줄 것
- 오늘 등록
- 미완료
- 가장 취약
- 오늘 추천 미션
- 내 오답노트
- 카메라 버튼

## 10.3 홈에서 보여주지 않을 것
- 랜딩 수준의 긴 가치 설명
- 가격 섹션
- 설득형 긴 카피

즉, 홈은 “행동 화면”이고,
랜딩은 “설득 화면”이어야 한다.

# 13. 개발 우선순위

## 1순위
- `todap.kr` 메인 진입을 랜딩페이지로 변경
- `/diagnostic` 신규 라우트 추가
- 랜딩 CTA를 `/diagnostic` 흐름으로 연결
- 로그인 redirect 처리 추가

## 2순위
- `users` + `diagnostic_sessions` 저장 구조 반영
- 무료 체험 상태 표시 추가
- `/app/*` 비로그인 접근 제어

## 3순위

- 홈/대시보드 역할 정리
- 가격/체험/유료 전환 고도화

# 14. 개발자용 직접 지시문

1. `todap.kr` 기본 진입은 앱 홈이 아니라 랜딩페이지로 변경한다.
2. 실제 앱은 `/app/*` 하위로 분리한다.
3. 랜딩의 모든 “무료 점수 진단 받기” CTA는 로그인 후 `/diagnostic`으로 연결한다.
4. `/diagnostic`은 신규 멀티스텝 무료 진단 페이지로 구현한다.
5. 진단 완료 후 결과 화면에서 “오답 5문제로 진단 정확도 높이기” CTA를 제공한다.
6. 무료 체험은 오답 5문제 기준으로 유지하되, 체험 데이터는 유료 전환 후 이어지게 한다.
7. 로그인 사용자라도 `todap.kr` 접속 시 기본은 랜딩을 보여주고, 상단에 “내 대시보드로 가기” 버튼을 별도 노출한다.
8. 앱 홈은 로그인 사용자용 행동 화면으로만 유지한다.

# 15. 최종 한 줄 결론

지금 토답은 앱을 먼저 보여주고 있지만,
매출과 전환을 위해서는 반드시 아래 구조로 바뀌어야 한다.

```text
랜딩
→ 무료 진단
→ 무료 체험
→ 결제
→ 앱 사용
```

즉,
`todap.kr`는 설득의 입구가 되어야 하고,
앱은 그 다음 단계가 되어야 한다.
