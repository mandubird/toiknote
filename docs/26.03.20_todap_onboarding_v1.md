# 토답 온보딩 개선 개발명세서 v1.1 (첫 3분 가치 경험 설계)

## 0. 목적
오답 등록 없이도 사용자가 **첫 3분 안에 가치(코칭 결과)**를 경험하도록 설계한다.
→ Day 1 이탈 방지 / 활성화율 상승

---

## 1. 핵심 문제
현재 구조:
랜딩 → 가입 → 오답 등록 → 코칭 결과

문제:
- 오답이 없으면 막힘
- 첫 액션이 무거움
- 가치 경험 전에 이탈

---

## 2. 목표 구조 (개선)

랜딩 → 가입 → 초간단 진단(4문항) → 즉시 코칭 결과 → 결제 CTA or 오답 등록 유도

---

## 3. 초간단 진단 설계

### 입력 항목 (4개)
1. 현재 점수 (select)
2. 목표 점수 (select)
3. 시험일까지 남은 기간 (select)
4. 가장 막히는 파트 (LC/RC/Part5/Part7)

👉 입력 시간: 10~20초

### 데이터 저장 방식
- 로그인 상태이면: `localStorage`에 저장 (`todap_onboarding_inputs` 키)
- 저장 시점: 4문항 모두 입력 후 "결과 보기" 버튼 클릭 시
- 유효기간: 7일 (이후 자동 삭제)
- wrong_answers가 3개 이상 쌓이면: localStorage 값 무시하고 실제 코칭으로 전환

```javascript
// 저장 예시
localStorage.setItem('todap_onboarding_inputs', JSON.stringify({
  current_score: 750,
  target_score: 850,
  days_left: 14,
  weak_part: 'Part7',
  saved_at: Date.now()
}))
```

## 5. 즉시 출력 (첫 가치 경험)

### 출력 구성

1. 약점 TOP3
2. 오늘 해야 할 공부 3개
3. 지금 버려야 할 공부 1개

### ⚠️ 중요: 임시 결과 레이블 필수 표시

결과 상단에 반드시 아래 문구 표시:

```
📋 간단 진단 기반 결과입니다
오답을 등록할수록 내 패턴에 맞는 코칭으로 정확해져요.
```

→ 배경색: 연한 노란색 or 회색 박스로 구분
→ 실제 AI 코칭과 **시각적으로 명확히 구분**

---

### 출력 예시 (700~800 + Part7)

약점 TOP3
- Part7 시간 부족
- 문장 구조 해석 오류
- 지문 스킵 기준 없음

오늘 할 공부
- Part7 5문제 시간 재고 풀기
- 틀린 문제 구조 분석
- 오답 3개 기록

버려야 할 공부
- 무작정 문제 많이 풀기

## 6. CoachingPage 표시 전환 조건 (충돌 방지)

> **핵심 원칙**: 온보딩 결과는 오답이 쌓이면 자동으로 실제 코칭으로 대체된다.

```
CoachingPage 진입 시 표시 분기:

IF wrong_answers.count >= 3:
  → 기존 AI 코칭 결과 표시 (정상 동작)
  → localStorage 온보딩 데이터 무시

ELSE IF localStorage['todap_onboarding_inputs'] 존재:
  → rule-based 임시 코칭 결과 표시
  → 상단에 "간단 진단 기반 결과" 레이블 표시
  → 하단 CTA: "오답 3개 등록하면 정밀 코칭으로 전환돼요"

ELSE:
  → 기존 빈 상태 화면 표시 (온보딩 진단 유도)
```

## 7. CTA 구조 (결과 화면 하단)

결과 화면 하단에 2개의 CTA를 배치한다.

### CTA 1 (메인) — 오답 등록 유도
```
👉 "오답 3개만 등록하면 정밀 코칭으로 바뀌어요"
→ /notes 또는 카메라 촬영 진입
```

### CTA 2 (전환) — 결제 유도 (Pro 플랜)
```
👉 "매일 코칭 + 전략 분석 받기"
   15일 29,900원 →
→ /payment 진입
```

> **배치 원칙**
> - CTA 1 (오답 등록): 상단, 더 눈에 띄게
> - CTA 2 (결제): 하단, 보조 역할
> - 두 버튼 모두 노출. 둘 중 하나만 선택하지 않음.

## 10. 개발 구현

### 프론트 컴포넌트
- `OnboardingDiagnosis.jsx` — 4문항 입력 스텝
- `OnboardingResult.jsx` — rule-based 결과 출력 (레이블 포함)
- `OnboardingCtaBar.jsx` — 오답 등록 + 결제 CTA 2개

### 로직
- `getOnboardingCoaching(inputs)` — rule 테이블 기반 결과 반환 함수 (순수 JS, API 없음)
- CoachingPage에서 `wrong_answers.count < 3`이면 localStorage 체크 후 온보딩 결과 표시

### 백엔드 (Supabase)
- **별도 테이블 불필요** (localStorage로 충분)
- 향후 전환율 분석이 필요하면 `onboarding_inputs` 테이블 추가 가능 (지금은 미구현)

## 12. Cursor 실행 프롬프트

```
온보딩 개선 구현 (v1.1):

1. OnboardingDiagnosis.jsx 생성
   - 4문항 입력 (현재점수/목표점수/남은기간/막히는파트)
   - 완료 시 localStorage['todap_onboarding_inputs']에 저장
   - 가입 직후 또는 CoachingPage 최초 진입 시 노출

2. getOnboardingCoaching(inputs) 함수 생성
   - API 호출 없음. 순수 rule-based JS 함수
   - 입력값(점수대 + 파트)에 따라 약점TOP3 / 오늘할것3 / 버릴것1 반환
   - 명세서 섹션 4의 규칙 테이블 기준 구현

3. OnboardingResult.jsx 생성
   - 결과 상단에 "📋 간단 진단 기반 결과입니다" 레이블 (배경 구분)
   - 약점TOP3 / 오늘할것 / 버릴것 표시
   - 하단 CTA 2개: "오답 3개 등록" (메인) + "매일 코칭 받기 →" (결제)

4. CoachingPage 분기 처리
   - wrong_answers.count >= 3 → 기존 AI 코칭 그대로
   - wrong_answers.count < 3 AND localStorage 존재 → OnboardingResult 표시
   - localStorage 없음 → 온보딩 진단 유도 화면

5. 예시 데이터 버튼
   - "예시 사용자 결과 보기" 버튼
   - 예시 결과 전체에 "이것은 예시입니다" 워터마크
   - 예시 모드에서는 localStorage 저장 금지
```

## 결론

👉 토답은 입력 기반 서비스가 아니라
👉 "즉시 결과를 보여주는 서비스"로 시작해야 한다

오답 등록 → 코칭이 아니라
**코칭 경험 → 오답 등록 → 결제** 순서로 퍼널을 재설계한다.
